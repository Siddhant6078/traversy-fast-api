# SID Fast API

A small issue-tracking REST API built with FastAPI. It supports creating, listing, retrieving, updating, and deleting issues. Issue data is stored in a local JSON file.

## Features

- CRUD endpoints for issues
- Pydantic request and response validation
- JSON-file persistence in `data/issues.json`
- Request duration returned in the `X-Process-Time` response header
- Interactive Swagger UI and OpenAPI schema

## Requirements

- Python 3.10 or newer
- `pip`

## Setup

From the project root, create and activate a virtual environment, then install dependencies:

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

If the virtual environment already exists, just activate it and install dependencies:

```sh
source .venv/bin/activate
python -m pip install -r requirements.txt
```

## Run the API

Run these commands from the project root (`sid-fast-api`):

```sh
source .venv/bin/activate
fastapi dev main.py
```

Or run the CLI directly without activating the environment:

```sh
./.venv/bin/fastapi dev main.py
```

The development server is available at <http://127.0.0.1:8000>. Open <http://127.0.0.1:8000/docs> for interactive API documentation, or <http://127.0.0.1:8000/openapi.json> for the OpenAPI schema.

## API endpoints

All issue endpoints use the `/api/v1/issues` prefix.

| Method   | Path                        | Description        | Success response |
| -------- | --------------------------- | ------------------ | ---------------- |
| `GET`    | `/api/v1/issues/`           | List all issues    | `200 OK`         |
| `POST`   | `/api/v1/issues/`           | Create an issue    | `201 Created`    |
| `GET`    | `/api/v1/issues/{issue_id}` | Get an issue by ID | `200 OK`         |
| `PUT`    | `/api/v1/issues/{issue_id}` | Update an issue    | `200 OK`         |
| `DELETE` | `/api/v1/issues/{issue_id}` | Delete an issue    | `204 No Content` |

Requests for an unknown issue ID return `404 Not Found`.

### Issue fields

- `title`: required on create; 3–100 characters
- `description`: required on create; 5–1,000 characters
- `priority`: `low`, `medium`, or `high` (defaults to `medium` on create)
- `status`: `open`, `in_progress`, or `closed` (new issues start as `open`)
- `id`: generated by the API

### Example: create an issue

```sh
curl -X POST http://127.0.0.1:8000/api/v1/issues/ \
  -H 'Content-Type: application/json' \
  -d '{"title":"Fix login bug","description":"Login fails for some users","priority":"high"}'
```

### Example: list issues

```sh
curl http://127.0.0.1:8000/api/v1/issues/
```

## Data storage

Issue records are read from and written to `data/issues.json`. If the file is missing or empty, the API starts with an empty issue list. Run the app from the project root so the relative `data/` path resolves as expected.
